Output: photoconsole/cli.py with click group + scan command, integration tests using click.testing.CliRunner on a real tmp_path fixture (no mocking of the scan pipeline — only ffprobe/rclone subprocess where unavoidable).

    Create photoconsole/cli.py with:

    1. Module-level click group: `@click.group()` decorated `main(ctx, verbose, quiet)`. Options: `-v/--verbose is_flag default False`, `-q/--quiet is_flag default False`. Use `@click.pass_context` and `ctx.ensure_object(dict)` to store {'verbose': verbose, 'quiet': quiet}. Validate that verbose and quiet are not both set; click.BadParameter if so.

    2. Configure logging in `main` based on verbose/quiet: verbose -> logging.basicConfig(level=INFO, format='%(asctime)s %(levelname)s %(name)s: %(message)s'); quiet -> level=ERROR; default -> level=WARNING.

    3. `@main.command()` `scan(ctx, config)` with `--config` `click.Path(exists=True, dir_okay=False, readable=True)`. Body: call `_run_scan(config, ctx.obj['verbose'], ctx.obj['quiet'])`; if return summary has errored>0 print a one-line warning; if quiet skip summary; otherwise print the summary table.

    4. `_run_scan(config_path, verbose, quiet) -> dict`:
       a. cfg = load_config(config_path)
       b. Dependency gates (BEFORE any scanning):
          - If any source.type == 'rclone' in cfg.sources: call check_rclone_available(); on RuntimeError, re-raise (let click.exceptions.ClickException or raise SystemExit handle it).
          - If cfg.include_extensions & VIDEO_EXTENSIONS is non-empty: call check_ffprobe_available(); on RuntimeError, re-raise.
       c. engine = create_catalog_engine(cfg.catalog_path); SessionLocal = session_factory(engine)
       d. Iterate `candidates = list(scan_all(cfg, verbose=verbose))`. (Listing is fine for ≤100K items per FR6.)
       e. With a Session, filter candidates by should_skip(session, path, mtime) where mtime = Path(path).stat().st_mtime if source_type == 'local' else fall back to None (rclone mtime handling deferred — for Phase 1 always process rclone candidates; document this in a comment with reference to Pitfall 6 in RESEARCH.md). Count skipped.
       f. Pass survivors to process_files(survivors, max_workers=cfg.hashing_max_workers, progress_cb=tqdm-based callback when not quiet).
       g. Maintain a buffer; every 50 results, open a Session, call upsert_many(session, buffer), session.commit(), clear buffer. After the iterator is exhausted, flush the remaining buffer the same way.
       h. Increment cataloged on status=='ok', errored on status=='error'.
       i. Return {'total_candidates': len(candidates), 'cataloged': cataloged, 'errored': errored, 'skipped': skipped, 'elapsed_seconds': time.monotonic() - start}.

    5. Wire tqdm progress: when verbose or default mode, wrap process_files in a try-with-tqdm.tqdm(total=len(survivors)) and update on each progress callback. Suppress when quiet.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI argv -> click | User-controlled flags and config path. |
| config.yaml -> load_config -> _run_scan | Already mitigated upstream; CLI re-validates path existence via click.Path. |
| Worker threads -> SQLite | Workers MUST NOT touch the DB. CLI enforces single-writer pattern. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Tampering | --config path traversal | mitigate | click.Path(exists=True, dir_okay=False, readable=True) validates before load_config; load_config uses yaml.safe_load (mitigated in Plan 01). |
| T-05-02 | Denial of Service | Worker threads writing to SQLite concurrently | mitigate | CLI design: workers return dicts; main thread does all DB writes in batches (Pitfall 2 in RESEARCH.md). test_writer_runs_in_main_thread enforces this. |
| T-05-03 | Information Disclosure | Verbose log writes file paths | accept | Paths are local user data, not secrets; user opts in via --verbose. |
| T-05-04 | Denial of Service | scan_all loads full candidate list into memory | accept | FR6 specifies up to ~100K items. ~100 bytes per tuple = ~10MB. Acceptable for Phase 1. Streaming refactor deferred. |
| T-05-05 | Repudiation | No audit log of scan operations | accept | Phase 1 is read-only on user files; no destructive operations. Audit log added in Phase 2 (consolidation) per ROADMAP. |
| T-05-SC | Tampering | click + tqdm supply chain | mitigate | Audited in RESEARCH.md Package Legitimacy Audit (both [OK]). |
</threat_model>
