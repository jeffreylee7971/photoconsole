<objective>
Extend the MediaFile ORM with 9 new Phase 3 columns (D-06) and add an idempotent ALTER TABLE migration to create_catalog_engine() so existing Phase 1/2 catalogs are upgraded on startup.

Purpose: Phase 3 columns are the substrate for every other plan — quality scores, embeddings, pHash, and cluster assignments all write to these columns. SQLAlchemy `create_all()` does NOT add missing columns to existing tables (verified in RESEARCH.md Q1/Pitfall 1) so an explicit migration is mandatory. The migration must be idempotent because `create_catalog_engine()` is called at the start of every CLI command.

Output: Extended `MediaFile` with 9 nullable columns; new `_ensure_phase3_columns()` helper in `db.py`; `create_catalog_engine()` calls the helper after `create_all()`; new `tests/test_catalog_phase3.py` proves the migration adds columns idempotently and that `upsert_media_file()` accepts partial dicts targeting only the new columns.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-03-02 | Tampering | _ensure_phase3_columns SQL injection via column name | mitigate | Column names and types are hardcoded in `_PHASE3_COLUMNS` constant (module-level, never user input). f-string interpolation is bounded to the hardcoded allow-list. Per RESEARCH.md Security Domain table — same approach as Phase 2 consolidator. |
| T-03-03 | Tampering | upsert_media_file unknown-column key injection | mitigate | Existing `_VALID_COLUMNS` allow-list (db.py line 142-147) rejects any key not in MediaFile.__table__.columns. | T-03-04 | Repudiation | Partial column upserts leaving inconsistent rows | accept | Existing UPSERT semantics: SET clause is dynamic per record dict; missing keys are simply not touched.
