## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| YAML config file -> ClusterConfig/QualityWeightsConfig | User-controlled cluster: and quality_weights: sections enter pydantic models |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-06 | Tampering | Config YAML integer overflow (eps, batch_size, sparse_threshold) | mitigate | pydantic v2 `Field(gt=0.0, lt=2.0)` for eps; `Field(ge=1, le=512)` for batch_size; `Field(ge=1000)` for sparse_threshold (per RESEARCH.md Security Domain table). Out-of-range values raise ValidationError before any computation. |
| T-03-07 | Tampering | Quality weights summing to != 1.0 silently produce wrong combined scores | mitigate | `@model_validator(mode="after")` asserts abs(sum - 1.0) <= 1e-6. Per AI-SPEC §4b.1 — "misconfigured weights are a silent correctness bug that is hard to diagnose after the fact". |
| T-03-08 | Information Disclosure | Pydantic ValidationError messages leaking config file path | accept | load_config wraps ValidationError as ValueError with the pydantic message. The path comes from CLI arg --config which is already user-supplied; no new information leakage. |
| T-03-09 | DoS | Recursive `cluster:` or `quality_weights:` YAML structures triggering deep recursion | accept | yaml.safe_load is already used (T-01-01 from Phase 1); pydantic discards unknown extra keys silently in v2 default mode — no recursion path. |
